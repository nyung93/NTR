# Nyung Trip-Plan — 여행 플래너

첨부 여행 플래너를 바탕으로 만든 React + Vite 애플리케이션입니다.

## 실행

```sh
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173
```

프로덕션 빌드: `npm run build`

회귀 테스트: `npm test` (Node.js 20.19 이상). 여행 삭제 테스트는 Firestore 트랜잭션을 모의 실행하며 실제 서버의 보안 규칙 검증을 대신하지 않습니다.

## 기능

- 여행 요약, 항공편과 숙소 카드
- 날짜별 일정, 일정 추가, Google Maps 검색 연결
- 두 여행자의 스파 프로그램 선택 및 이용 횟수 관리
- Firebase 계정별 여행 저장과 이메일로 여행 공유
- 데스크톱 사이드 메뉴와 모바일 하단 메뉴

스파 플래너는 개인 여행 계획이며 실제 예약을 전송하지 않습니다. 여행 데이터는 Firestore에 저장하고 브라우저에는 캐시를 보관합니다. 사용자가 제공한 사타호텔·퓨전리조트·나트랑 해변 사진은 프로젝트에 포함되어 외부 이미지 접근 없이 표시됩니다.

## 여행 관리

왼쪽 여행지 선택(모바일은 화면 상단)에서 여행을 전환하거나 추가할 수 있습니다. 여행지·출발일·마지막 날을 입력하면 최대 90일의 빈 일정표가 생성됩니다. 기존 나트랑 일정과 스파 선택은 유지되며 새 여행의 일정은 별도로 저장됩니다.

같은 이름의 여행은 선택 목록에서 여행명 옆 `나` / `공유` 라벨로 구분할 수 있습니다. 중복된 개인 여행만 지우려면 `나` 라벨이 붙은 여행을 선택한 뒤 **여행 정보 → 여행 삭제**를 누르고, 확인창에서 공유 여부를 확인하세요. 선택한 여행의 문서 ID만 삭제하므로 같은 이름의 다른 여행은 보존됩니다.

삭제는 소유자만 가능하며 여행 본문과 `planner`의 `overview`, `itinerary`, `budget`, `spa`를 하나의 트랜잭션으로 삭제합니다. 전체 `planner` 컬렉션 조회는 사용하지 않습니다. 삭제 기록은 소유자의 `users/{uid}/planner/deleted-trip-{tripId}`에 남기며, 이전 데이터를 다시 가져올 때 이 기록을 확인해 삭제한 여행이 재생성되지 않도록 합니다. 삭제 기록은 유지해야 합니다. 이 동작은 현재 저장소의 Firestore 규칙을 사용하며 별도의 규칙 완화가 필요하지 않습니다.
